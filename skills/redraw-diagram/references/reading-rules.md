# 读图纪律

> 这份文件里每一条，都是**踩出来的**，不是想出来的。
> 每条都注明了"怎么发现的"，这样你可以判断它值不值得信。

## 一、关于"我怎么读"的规矩：可以记死

这些是**我自己的工作方式**，跟图的作者是谁无关，稳定、通用。

### R1　方向和箭头个数，禁止在全页视图上判断

**必须放大到能看清箭头头部。**

- **怎么发现的**：一条黄色双向箭头，在全页视图下只有 16×50 px，两个箭头头部各约 7 px。
  我把它看成了"朝下的单箭头"，于是把"一组对一组双向"读成了"上面流到下面"，
  还差点写成"原件表达不清"。
- **同一个错法换了个形式又出现一次**：另一页有个旋转 180° 的右箭头，
  不放大就会把方向读反。
- **代价**：这两次我都**先把锅推给了原件**。第二次差点写进交付物，
  作者会被要求去改一个本来没毛病的地方。

### R2　组内元素给的是「组内坐标」，不是页面坐标

```
abs = 组的位置 + (子元素坐标 - chOff) × 缩放
```

**漏掉 `(子元素坐标 - chOff)` 的后果特别阴**：所有尺寸都对，只有位置整体平移。

- **怎么发现的**：改完之后眼睛看预览觉得"怪怪的"，又说服自己没事。
  最后是**像素采样**抓出来的——采"粗黑箭头"的位置，返回的颜色是粉色。
- **规矩**：**坐标换算不许手算，一律让脚本按数据算。**

### R3　显式写了的颜色，优先于采样

原件 XML 里如果明确写了颜色，就用它；只有继承主题（没写）时才去渲染图里采。

- **为什么**：采样会被**穿过的元素**污染。一条深蓝分隔线被黄箭头穿过，
  采出来就是黄的。
- **本质**：**XML 里的值是原件的事实，采样只是渲染的近似。**

### R3.5　「我不知道」和「没有」，必须分开表示

**这是这个项目反复栽的一个坑，而且每次换一层皮。**
只要两种意思共用同一个空值（`None` / `""` / `0`），
那么**任何为「不知道」写的兜底，都会悄悄吞掉「没有」**——而且吞得没有声音。

规矩：**每一种状态都要有自己的名字**，不许塌缩。至少要能区分：

| 状态 | 意思 | 该怎么处理 |
|---|---|---|
| 明写了 | 原件写死了值 | 直接用 |
| 写了主题色 | 明写了，只是要查主题表 | **解析它**（含 `lumMod`/`tint` 等修饰符） |
| 明确说没有 | `noFill` / 没有 `<a:ln>` 且没有 `lnRef` | **就是没有**，不许猜 |
| 主题给了 | 没写死，但 `lnRef`/`fillRef` 指了 | 去看它长什么样（可以采样） |
| **读不到** | 有元素但读不出来 | **报出来**，不许静默填默认值 |

实测被抓出来的（2026-10，全部先在真材料上复现，再修）：

| 塌缩 | 症状 |
|---|---|
| 「没有 `<a:ln>`」≡「有 `<a:ln>` 但颜色在主题里」 | **4 个形状被凭空加了边框**，采到的"边框色"是文字自己 |
| 「`schemeClr`（明写了）」≡「没写」 | 绿条上的白字标题被采成深藏青；反方向上，**主题色描边被静默丢掉** |
| 「渐变填充」≡「没写填充」 | 渐变被**采成一个平色** = 把渐变假装成纯色 |
| 「字号写在 `defRPr` 里」≡「没写字号」 | 静默变成 10pt / 微软雅黑 |
| 「主题里查不到」≡「没写」 | 静默变成 `333333`，一声不响 |
| **「没见过的对象类型」≡「没有对象」** | **10 个表格被静默吞掉，而 `stats` 报 `unsupported: 0`** |

**最后那条要单独说**，因为它换了层皮、而且**两头一起瞎**：

原件的形状类型不止 `<p:sp>` ✗ —— 表格和图表是 `<p:graphicFrame>`：
- **读的那一头**：`Xfrm` 只在 `a:` 命名空间里找 `xfrm` ✗，而图形框是 **`p:xfrm`** ✗
  → 找不到就 `continue` ✗ → **连"不支持"都到不了** ✗
- **对账的那一头**：`if not sh.has_text_frame: continue` ✗
  表格**没有** `text_frame` ✗ → 原件那一侧**等于没有这些文字** → 它也报不出"遗漏" ✗
- **两头都瞎，所以这个洞很久没被发现** ✗
  （另一个原因：**另外两份示例材料里都没有表格** ✗ —— 只测一种材料，测不出这个 ✗）

> ⚠️ 同一个坑代码里**已经记过一次**（`<p:spPr>` 是 presentationml 不是 drawingml ✗）——
> **换了个元素又踩一遍** ✗。看到"按命名空间找元素"时，先问是不是该按**本地名**找。

**可操作的保护 —— 账要对上**：

```
数一遍：  读到的 + 记下来的（不支持/降级） = 原件**实际有的**
对不上 → 有东西无声消失了 ✗
```

★ 注意**表格算一个对象**（它的格子是内容，不是新对象 ✗）——
所以这条账在"表格展开成格子"之后，算的不是 `len(shapes)` ✗。

**顺带一条**：`bg1` / `tx1` / `bg2` / `tx2` **不在 `<a:clrScheme>` 里**，
它们是**别名**，映射表在母版的 `p:clrMap` 上。漏了这层，32 处会解析不出来
——而这正是靠"不许静默"那条告警发现的。

> **判据**：如果你在代码里看到 `x is None` 后面跟着一个兜底分支，
> 先问一句：**这个 `None` 有几种意思？** 超过一种，就是这里。

### R4　描边的粗细要量，不要猜

- **怎么发现的**：用户说"文字压住了边框"。我先去调文字位置——
  **量了才知道，文字位置一行不差，是描边粗了一倍**（原图 0.5pt，我画了 0.9pt）。
- **规矩**：**先量，再改。** 看着像 A 的问题，可能是 B。

### R5　中文必须显式设 `ea`（东亚）字体

只设 `latin`，中文会回落到主题默认字体，**字宽不一样**，会偏大、多余换行。
原图是 `latin` + `ea` 都设同一字体，还带 `panose` / `pitchFamily` / `charset`（GB2312）。

### R6　`wrap`（换不换行）和 `overflow`（溢出了怎么办）是两件事

把"不换行"当默认，字会被撑出框外。
原件 `bodyPr` 里通常两个都有，**要分别读**。

### R7　文本框的内边距不要设成 0

OOXML 的默认是左右 0.1 英寸、上下 0.05 英寸（150dpi 下约 15px / 7.5px）。
设成 0，文字会整体往左上偏。

### R8　不能亲眼验证的输出，必须做源码级检查

有一类输出我渲染不出来（比如某些环境下的 SVG）。这时候：

- **数结构性特征**：`<marker>` 定义了几个、引用了几个；路径有几个顶点；
  双向箭头是否**顶部和底部各有尖**
- **把"我改了什么"验证到底**：比哈希、看 mtime、grep 关键字段

- **血的教训**：我插代码时破坏了缩进，脚本报 `IndentationError` 直接不执行，
  而**我把报错重定向掉了**。于是我以为改了、其实一行没生效，
  还反复渲染**旧文件**"验证"了好几轮。**是产物的哈希一直没变才抓出来的。**

→ 两条死规矩：
1. **构建脚本的 stderr 绝不许吞掉。**
2. **每轮必须验"产物真的变了"**，不能只看命令有没有报错。

### R9　组坐标、pt/px、原图/画布——同一类换算我错了三次

全部归到 R2：**不许手算。**

## 二、关于"这个作者什么意思"的：**只能当假设**

⚠️ **这一节不是规矩，是假设。**

每个作者都有自己的习惯。**记死了只会限制自己**，而且规则越攒越多、迟早打架。
正确的姿势是**不懂就问**。

下面这张表来自**一份 PPT**（一份真实的 IT 运维产品资料），
**只有这一页的孤证**，换一份 PPT 可能全不成立。

| 视觉特征 | 在这份 PPT 里 | 证据强度 |
|---|---|---|
| 实线 | 同层内的流程走向 | 一页 |
| 虚线 | **另一种关系**（异步 / 人工介入 / 子流程调用，都有） | 一页 |
| 粗黑箭头 | **跨层** | 一页 |
| 主题强调色箭头 | **关系 / 后续路径** | 一页 |
| 双向箭头 | 双向（1对1 直接接方块；组对组接括号） | 一页 |
| 大括号 | **分组**（把几个方块括成一组，让双向箭头作用在"组"上） | 一页 |

**这张表自己就给出了反例**：

- 同一页里两条虚线**样式都不一样**（作者笔误）
- "黄色"其实是**主题强调色**（`schemeClr accent3`），换一份 PPT 就是另一个颜色

→ **把作者习惯记成铁律，下次遇到另一个作者就会先入为主、不再去看。**

### 附：一种常见偷懒 —— **拿表格当背景板**

**（假设，证据强度：一页。但信号是机械可查的，所以值得先算出来再问。）**

实测那份资料的第 1 页，10 个"表格"里有 **5 个根本不是表格** ✗：

| 信号（**机械可查**） | 它在干什么 |
|---|---|
| **1×1**（只有一格） | 就是**一个色块** ✗ 不是表格 |
| **有不属于它的形状压在它上面** | 它是**背景板** ✗ 上面浮着别的东西 |

实测：

```
sp216 服务层      1×1                       → 色块 ✗
sp246 基础能力     1×1                       → 色块 ✗
sp247 采控平台…    1×1                       → 色块 ✗
sp217 数据层      2×2，**15 个东西压在它上面**  → 背景板 ✗
其余 5 张         格子都有字、没东西压着        → 真表格 ✓
```

> ★ **为什么值得单独拎出来**：
> 这**不是我们的读法问题，是原件的偷懒** ✗ ——
> 用一张大表当色板，比老老实实画一个矩形省事 ✗。
>
> **重排的时候不该学它** ✗ —— 该把它**降级成一块容器/色板** ✓，
> 再把浮在上面的东西**规规矩矩排进去** ✓。

**怎么处理**：算出来 → **当假设列给用户看** ✓ → 用户点头再降级 ✓
**不许默默降级** ✗ —— 那也是改作者的意图 ✗

## 三、空白有三种，含义完全不同

| 种类 | 含义 | 处置 |
|---|---|---|
| **我没读出来** | 我的问题 | 去查。**一个字都不许问用户** |
| **原件里没有** | 缺失，本身是证据 | 记下来，标"原件没说" |
| **原件故意留空** | **"这里放你自己定义的任意步骤"** | **一个字都不许填** |

第三种最容易搞错，也最危险：**填上名字，元素数没变，但图的定位被改了**
（从"卖能力"变成"卖一个具体流程"），**等于把作者的意图改了**。

### 怎么分辨？靠**对照**，不靠这张图本身

实例：一张四层架构图里，**"工具服务层/执行层"全部具名，"流程引擎层"全部留空**。
分界线不是随机的：

> **列举 = 必须具名**（这层的价值是"我有哪些"）
> **结构 = 必须留空**（这层的价值是"我能做出哪些形状"）

跨页对照更说明问题：同一份 PPT 里另一页也是流程图，**每步都写满了**——
因为那页讲的是**一个具体流程**，而这页讲的是**引擎的能力**。

→ **有些意思只能从对照里读出来。** 单看一张图，永远读不出"空白 = 由你定义"。

### 附带一条：编号可以，命名不行

在标号图上给空框编号（N1、N2）是**指代**，方便用户指着说"这个"。
**给它们起名字，就是把我的理解冒充成图上的内容。**

## 四、找不到答案时，先分清楚是谁的问题

"不确定"有两种来源，处置完全相反：

```
去查
├── 回去看原件      —— 答案在原件里，我没读出来
└── 回去修我自己    —— 原件没毛病，是我的模型 / 校验器 / id 方案有毛病
```

第二种**永远不该变成问题**，而且它**伪装成"原件质量差"**。

实例：一份原生 PPT 里，形状名和几何方向打架、形状名不唯一、
容器套容器装不下——这些看起来都是"文件质量差"，**其实全是我的问题**。
而这类错在**位图页上根本不存在**，所以只测位图页发现不了。

→ **怀疑原件之前，先放大到极限再看一遍。**
