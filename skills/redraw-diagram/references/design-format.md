# ② 设计稿 —— 格式

> **它是「读」和「画」之间的交接物。**
>
> ```
> ① 读     →  清单（有什么 / 谁指向谁 / 是什么关系）        有坐标吗？没有
> ② 设计   →  **本文件**（每条关系用什么表达 / 组合倾向 / 角色锚点）   有坐标吗？**没有**
> ③ 画     →  SVG / PPTX                                    有坐标吗？**有，坐标在这一步才出现**
> ```
>
> ★ **一句话**：② 回答「**用什么方式表达**」，③ 才回答「**放在哪**」。
> **把两步合成一步，就会出我们踩过的那个坑**（见文末「为什么要有这一层」）。

---

## 0. 谁产出、什么时候产出

| | |
|---|---|
| **谁** | **画（③）的那一方**。它拿到 ① 的清单后，**先写这一份，再动手画**。 |
| **什么时候** | 动笔写第一个坐标**之前**。 |
| **要不要落纸** | **要** ✗。不落纸它就会消失——我们实测过：只在脑子里过一遍，画的时候就凭手感，C3/C4 就摆错了。 |
| **一页一份还是一张图一份** | **一张图一份**（我们产出的是图，不是整套 deck）。 |

**⚠️ 它不许自带坐标**（见 §2），因为它的用途正是**把"怎么表达"和"放在哪"分开**。

---

## 1. 五节，一节不能少

````markdown
# ② 设计稿 · <这张图叫什么>

## 一、拓扑判断

**topology = `yes` | `no`**

- `yes` —— 几何**必须承载**这页的关系（流程图、架构图、泳道图、示意图…）
- `no` —— 几何**不承载**关系（纯罗列、纯文字页）

**理由**：<一句话>

## 二、Relationships（来自「读」，**来源明说的**）

| 关系 | 从 | 到 | 类型 |
|---|---|---|---|
| C1 | 持续集成（CI） | 制品库 | `order` |
| C3 | CMDB | 应用部署（CD） | `link` |

**分组**：<哪个容器装谁>
**归属**：<哪条标注在说哪条关系>

> ⚠️ **这一节里不许出现形状、载体、或任何编排用语** ✗
> 只写「谁和谁是什么关系」。写法的问题一律留给第三节。

## 三、每条关系**用什么表达**   ← 本文件的核心

| 关系 | 类型 | 表达方式 | 依据 |
|---|---|---|---|
| C1 | `order` | 线（带箭头） | `order` → Position, numbering, direction, shared path |
| C5 | `link` | 位置：<哪个东西贴在哪个东西的正下方/正侧> | `link` → Proximity / alignment **when unmistakable** |

**表达方式只能从这五个里选**（借 `executor-structure.md` §1 的 Encode with）：

| 表达方式 | 什么时候用 |
|---|---|
| **线** | 位置说不清的时候。**默认兜底**。 |
| **位置** | 邻近/对齐**一眼看得出来**的时候 |
| **包含** | 「A 属于 B」这类 |
| **次序** | 有序阶段（配合编号） |
| **并排** | 同类比较 |

> ★★ **同一套判据**（`link` 和 `order` 都是这一条）：
> **能用位置说清的，就别加线；说不清，就画线。**
>
> **用「位置」的，必须在「依据」里写出"为什么说得清"** ✗
> ——比如「正下方、水平居中、中间没有别的东西、还带编号」✓
> ——比如「周围有无关的邻居更近」✗ → **说不清 → 改画线** ✓

## 四、组合倾向（`Composition` —— **起手草图，可自由改**）

```
上：<一句话>
中：<一句话>
下：<一句话>
```

**分区**：<每块一个组，列出来；**组与组之间不许重叠**>

> 这一节是**草图**，不是约束。画的时候可以改 ✓
> 标 `(binding)` 的除外——那表示"必须照做"。

## 五、角色锚点（**角色级**，不是每个对象一个值）

| 角色 | 用途 | 字号 | 填色 | 文字色 |
|---|---|---|---|---|
| 节点 | 流程主干 | 20 | 主蓝 | 白 |
| 标注 | 说明文字 | 12 | 浅灰底 | 深灰 |

**间距锚点**：几档、各管什么（页边距 / 块间距 / 组内间距）
````

## 2. 允许什么、禁止什么（这是**边界**，不是建议）

| | 允许 ✓ | 禁止 ✗ |
|---|---|---|
| **数值** | **角色级锚点**：一个角色一个字号 / 一个色 / 一档间距 | **每个对象一个值** |
| **几何** | 相对关系：「正下方」「并排」「居中」 | 坐标、点、尺寸、比例、调整值 ✗ |
| **颜色** | 语义角色（主色 / 强调 / 正文 / 分隔）+ 一个锚点色值 | 每个对象的填色 ✗ |
| **字体** | 角色的字体与字号锚点 | 每个对象的字号 ✗ |
| **画法** | 第三节写「线 / 位置 / 包含 / 次序 / 并排」 | 形状名、SVG 片段、路径数据 ✗ |

**判据一句话**：

> **一个值服务一个"类" → 允许 ✓**
> **一个值服务一个"东西" → 禁止 ✗**

**量出来的数字（距离、偏差、框宽…）不属于本文件** ✗ —— 那是对**输出**的检查 ✓
放进 §6 或单独的检查记录里 ✓

## 3. 画出来的东西，**id 要能对上清单的 id**

> ★ 这一条是建 `reconcile.py` 的时候才撞出来的 ✗ ——
> 没有它，「清单里说该表达的，输出里表达了没有」**根本对不了账** ✗。

画（③）的时候：

| 画的是什么 | id 用 |
|---|---|
| 实体的框 / 卡片 | **实体 id**（`N1`、`T3`…） |
| 关系的线 | **关系 id**（`C1`、`C10`…） |
| 容器 / 分区 | **分组 id**（`G1`、`G2`…） |

**为什么**：
- 对账工具要靠 id 把「清单」和「输出」连起来 ✗ 对不上只能猜 ✗
- 而且 id 会变成 **PPTX 里的形状名** ✓ —— 用户在 PowerPoint 里点一个框，就能看到它对应清单里的哪一条 ✓

**⚠️ 必须一字不差，包括分隔符** ✗ ——
实测我把 `BAND_前台业务`（下划线）画成了 `BAND-前台业务`（横杠）✗，
→ 10 条"表 ∈ 带"的关系**当场全对不上** ✗。
**不要自己另起一套命名** ✗。

**对不上怎么办**：`reconcile.py` **直接报错，不猜** ✓

## 4. 机器能查什么

`check_design_doc.py` 查三件（都是硬规则，不涉审美）：

| 检查 | 判据 |
|---|---|
| **五节齐不齐** | 缺节 = 失败 |
| **有没有坐标漏进来** | **除「五、角色锚点」外，别处出现带单位的长度/坐标 = 失败** |
| **每条关系有没有表达决定** | 清单里的关系，第三节漏了谁 = 失败 |
| **用「位置」的是否写了理由** | 写了「位置」但「依据」为空 = 失败 |

> **它查不了"这个决定好不好"** ✗ —— 那是审美，只有人（或另一双眼睛）能判 ✓

## 5. 为什么要有这一层（我们踩过的坑）

**实测**：第一版我**跳过了②**，从清单直接手写 SVG ✗。

```
我脑子里想的是：  "C3 是 link，用邻近表达" ✓
我手上画的是：    CMDB 摆在了【制品库】旁边 ✗
量出来：          离制品库 265px，离应用部署 297px
                  → 一个毫无关系的邻居更近 ✗
                  → "unmistakable" 不成立 ✗
                  → 按规则本该画线 ✗
```

**补上②、把"用什么表达"写下来之后**，同一条规则就生效了：

```
写的时候必须引规则 → 规则说 "when unmistakable; otherwise an edge"
→ 一量，说不清 → 改画线 → 两端都贴上了 ✓
```

> **写下来这一步不是形式主义。它逼你引规则，而不是凭手感。**
>
> 而且：**只在脑子里过一遍，它就会在动笔的时候蒸发** ✗

## 6. 和 ppt-master 的对应关系

本文件是它的概念在我们场景下的落地，不是另起一套：

| 本文件 | ppt-master 里对应的 |
|---|---|
| 一、拓扑判断 | `executor-base.md` §2.2 **Step 3 — topology decision** |
| 二、Relationships | `design_spec.md` §IX 的 **`Relationships`** 行（含"不许提形状/载体"那条硬规矩） |
| 三、表达方式 | `executor-structure.md` §1 的 **Encode with** 那一列 |
| 四、组合倾向 | §IX 的 **`Composition`**（Reference，可自由改；`(binding)` 才不许改） |
| 五、角色锚点 | §III 配色角色 + §IV 字号层级 + §V 间距锚点 |
| （不落纸） | 它把①的 `Relationships` 落成 §IX 一行；**Quick 路线没有 spec/lock，所以我们自己落纸** ✗ |
