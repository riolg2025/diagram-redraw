# 重画一张图

把人类画的图，重画成**可编辑**的版本。核心不是"画得出来"，是**"画的和人理解的一致"**。

## 铁律（先记住这三条）

1. **先问清楚，再动手。** 不要上来看一眼就开始画。
2. **元素不增不减。** 一个不多、一个不少。
3. **要改先问。** 觉得该增减、或者看不清，先问。**这条包括原件的毛病**——
   原件有错也**原样照抄**，然后告诉用户"这里我没动，你要不要改"。

---

## 流程

### 第 0 步：确认范围 —— 第一件事，不是读图

真实场景里，**用户给的 PPT 里，图往往只是页面的一部分**。

先渲染出这一页（`render_pptx.py`），看一眼，然后**明确问用户**：

> 你要我理解的是哪一块？要重画的是哪一块？

别自己猜。不问清楚，很可能画出来他要的东西根本不在里面
（比如把文字卡片也画进去、却画不出那些界面截图）。

### 第 1 步：读

```bash
python3 scripts/render_pptx.py deck.pptx --pages 5 --outdir work/orig
python3 scripts/read_slide.py deck.pptx --slide 5 --region x,y,w,h \
        --render work/orig/page-0005.png --out work/spec.json
```

`read_slide.py` 会打印两件必须转达给用户的事：

- **有多少个形状是没有文字的** → 默认按「原件故意留空」处理，**一个字都不许填**
  （除非用户确认那是没画完）
- **有多少个对象画不出来** → 必须主动说，别让用户以为都画上了

读图时会踩的坑，全在 `references/reading-rules.md`。
**动手改之前先读那份**，尤其是"方向和箭头个数必须放大看"和"组坐标要变换"。

### 第 2 步：标号图 —— 让用户扫一眼就能核对

```bash
python3 scripts/mark_slide.py work/spec.json work/orig/page-0005.png --out work/marked.png
```

**这是整个流程的第一句话**：不是"我看到了 18 个节点"这种文字，
而是**一张标了号的图** + 一句话："这些我都看到了，对吗？"

为什么这样做（实测有效）：

- 用户**扫一眼就能答**（"对"/"少了一个"），不用想、不用打字、不用描述风格
- 它把"AI 想当然"的风险**摁死在第一步**
- 它对"不看技术文档"的用户友好 —— 图片谁都会看

### 第 3 步：问

按 `references/ask-when.md` 走：**内容问题尽量别问；任务问题主动问，而且问在前面。**

必须问到的（这些推不出来，猜错了整张图白画）：

- 重画的范围（第 0 步已问）
- 输出要 PPT 可编辑、还是 SVG、还是都要
- 配色跟谁（**"跟不跟你的模板"是任务问题，不是审美问题**）

**审美问题不要问** —— 配色、间距、字体，自己定就行。

问的时候：**给选项，不给开放题**；每个问题要说得出"答错会改什么"。

### 第 4 步：画

```bash
python3 scripts/build_deck.py work/spec.json --pptx work/out.pptx --svg work/out.svg
```

### 第 5 步：自检 —— 不许跳过

```bash
python3 scripts/render_pptx.py work/out.pptx --pages 1 --outdir work/redraw
python3 scripts/verify.py <原图> work/redraw/page-0001.png --outdir work/diff
python3 scripts/svg2png.py work/out.svg work/svg-render.png
```

**看差分图，不要只看"像不像"。** 实测能抓出来的东西：

- 文字整体偏移（肉眼几乎看不出）
- 描边粗一倍（看起来像"文字压边框"，其实是线的问题）
- 菱形画成了方框
- 最阴的一种：**脚本报错没跑，却在"验证"上一轮的旧文件**

判据：**显著差异像素超过 15% 就别交付**，先查。
剩下的差异多是边框 1px 取整偏移，和渲染环境缺字体。

### 第 6 步：交付，并说清楚边界

交给用户时，**必须主动说**：

- **哪些对象没画**（自由曲线图标、位图截图……）
- **我改了原件的什么**（如果动了）
- **哪些地方是我推的**（不是从图上直接读出来的）

---

## 输出的两种格式，分别给谁

| | 给谁 | 为什么 |
|---|---|---|
| **PPTX（可编辑形状+文字）** | **给人** | 用户能点开就改、拖、换色 |
| **SVG（矢量）** | **给机器和网页** | 放大不糊、能塞网页、文字可读 |

两者本质是同一类东西（都是"图纸"），所以**画一次、翻两次，成本很低**。

**注意**：位图截图在 SVG 里也只能当图片嵌进去（base64），改不了。

---

## v0.1 的边界（要主动告诉用户）

- **只覆盖 PPT 里的原生矢量图。** 位图页、手绘照片、PDF 输入都不支持。
- **自由曲线（FREEFORM）画不出来** —— 常见于图标。会被列进"画不出来"的清单。
- **表格不支持。**
- **只在两份真实页面上验证过。** 机制是通用的，覆盖面很窄。

遇到不支持的输入，**直接说不支持**，不要勉强画一个看起来像的。
