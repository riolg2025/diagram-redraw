## 工具链上撞的坑（会重复踩，记下来）

1. **直接渲染是空白的。** bundled LibreOffice 渲染这份 PPT 的 6 页，**全部空白**，六页字节数一模一样（5,649 字节）。改成**先转 PDF，再从 PDF 取图**（走 pdfium）就正常了。

# ★ 这一轮最重要的一条：我把用户的回答理解错了

```
我问的：C10 和 C11 算一条关系还是两条？
用户答的：是一条折线关系        ← 原话
我记的：  关系数 = 10           ← 我自己挑的解释，错的
```

用户说的"折线"是**形状弯了**；我问的是**关系数量**。**用户的回答没问题，
是我的问题本身有歧义，而我没有回问，挑了个方便自己的解释记成了事实。**

后果很具体：**我在重画时把一个箭头删掉了。** 如果用户没回头看那张图，这个错就留在交付物里了。

## 为什么这个错被发现

**唯一的原因是原始回答被逐字留着，没有被我的解读覆盖。**

`inventory.json` 里现在的结构：

```
user_evidence[0]  answer: "是一条折线关系"     ← 原话，一个字没改
                  my_interpretation: {关系数: 10, status: "已作废（见 u002）"}
user_evidence[1]  = u002，用户澄清：箭头代表双向关系
lessons[0]        = 这次的教训
```

**如果当时直接写"用户确认为一条关系"，这个错就永远埋在文件里，而且下次画图还会照错的画。**

## 已经变成规矩的两条

写进 `../REQUIREMENTS.md`：

1. **回答也可能是歧义的。不许自己择一，要回问。**
   尤其当对方用的词和问题的问法不在同一个维度时（这里：形状 vs 数量）。
2. **回答必须逐字留档，和我的解读分开存。**
